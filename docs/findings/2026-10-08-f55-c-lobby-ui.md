## What the slice is

The stage table and the producer/consumer wiring the sheet asks for: the
screen produces typed requests, the link hands them to `cs_net::lobby::Lobby`
(the single owner of lobby truth), and the events that come back are the
only display input there is.

```
host form ──submit_host──▶ HostSettings ──▶ LobbyLink::host ──▶ Lobby::open
join form ──submit_join──▶ JoinRequest  ──▶ LobbyLink::join  ──▶ Lobby::admit
room actions ────────────▶ LobbyCommand ──▶ LobbyLink::command ─▶ Lobby::apply
                                                                  │
                                        Applied::events ──────────┘
                                              │
                     acting screen observes them; the application fans
                     them out to every other local screen (LobbyView)
```

- **Stage table.** `Stage::{Join, Host, Room}` with an explicit refusal
  ([`LobbyUiError::WrongStage`]) for every action outside its stage, and a
  `back` path that tears the room down first and leaves the screen (dropping
  the drafts) from a form. Focus is a control of the current stage and
  resets to the stage's first control on entry.
- **Join.** Direct address, callsign and password. The address is validated
  for shape only; the endpoint behind `submit_join` is supplied by the
  caller. Admission itself is `Lobby::admit`, so the check order (password →
  content → phase/late join → capacity → callsign) and the distinct
  [`JoinError`] variants are the domain's, not the screen's.
- **Host.** Scenario (a **content id**, never a row number), callsign,
  password, member cap, team mode, late join, host-loss policy. Nothing is
  defaulted into existence: scenario, callsign, password and cap start unset
  and the form refuses to submit until they are entered.
- **Team / loadout / readiness / chat / host rules.** Each is a
  `LobbyCommand` the lobby re-validates (authority, phase, revision, bans,
  shared validator); the screen never edits a member or a rule.
- **Teardown and retry.** A refused join leaves the stage, the draft and the
  endpoint untouched; `leave` removes the player from the lobby, resets the
  screen to the join form and keeps the draft for a retry; `back` on a form
  discards the drafts and leaves the screen.

## Decisions

- **The screen never owns the connection.** Every action takes
  `&mut LobbyLink`; only `submit_host` *returns* the link it opened. That is
  the `UI-NETWORK` rule read literally: the screen requests a domain
  transaction and holds no domain state.
- **The validator is injected, never invented.** `Lobby::apply` requires a
  `LoadoutValidator`; `cs_net` cannot depend on the content crates and no
  production implementation exists (#764), so `LobbyLink::host` demands one
  from its caller instead of assuming a permissive default. The tests supply
  an explicit accepting validator, as F55-A and F55-B did.
- **A refusal is kept on the screen, not thrown away.**
  [`LobbyScreen::refusal`] holds the last `LobbyUiError` until an accepted
  action clears it, so a form error is still on screen while the player
  corrects it. `LobbyUiError::message_key` is distinct for every
  `JoinError`, which is what makes AC03 a screen property rather than a
  domain-only one.
- **Chat is text, never markup.** The bound and the control-character rule
  are `ChatText::new`'s; the screen stores and displays the literal string
  and the escaped form stays the renderer's business.
- **The host's own departure follows the declared `HostLoss` policy**, so
  leaving from the host screen reports `Departure::LobbyClosed` /
  `LobbyPaused` rather than silently dropping the lobby.
- **`LobbyView` gained `MemberJoined` / `MemberLeft`.** "Disconnected
  clients leave cleanly" (non-negotiable 4) needs the departure to be
  displayable; the projection previously dropped both events.

## Open / not claimed (resolving tasks)

- **No socket, no remote endpoint.** `submit_join` submits to a link the
  application supplies; resolving the join form's direct address, and LAN
  discovery, need a transport (`cs_net::message`/`lifecycle` and a socket),
  which is outside this task's owner paths, and the lobby packet envelope is
  still not carried on the F54 session wire (**#763**, `F55-BU1-WIRE`). No
  claim of remote joining, LAN discovery or Internet connectivity is made
  for F55-C. Discovery and connectivity are never conflated: the form holds
  an *address* and this module contains no matchmaking wording at all.
- **The lobby screen is not reachable from the menu.** The front-end state
  table lives in `crates/cs_app/src/ui/front_end/`, which is not an F55
  owner path, so `Screen::ALL` still has no lobby screen. Filed as
  **#787 (F55-CU1-ENTRY)**.
- **`crates/cs_content/src/lobby.rs` was not created.** The host form takes
  a scenario content id from its caller; a *menu* of the installation's
  multiplayer scenarios comes from F56-A's measured `SlotCatalog`
  (`multiplayer::discover_slots`) and belongs with the same application
  wiring that is out of this task's owner paths. There is no content-side
  lobby data this stage can add without guessing. Filed as
  **#788 (F55-CU2-SCENARIO-MENU)**.
- **`LoadoutValidator` still has no production implementation** (#764):
  budget/fitment validation of lobby loadouts remains unproven. The host's
  own bans, the shape checks and the injected validator hook run.
- **No original lobby options.** Scenario ids shown to a host, the default
  player count, team modes, late-join and host-loss defaults of the original
  PC game are unmeasured (F55-D, #476). Every value in `HostDraft` is
  either unset or documented as a designed initial state.
- **Ping, pilot voice and per-mode late-join tables** are not in this stage
  (F55-C wording covered discovery/connectivity only; #476 measures the
  per-mode rules).
- **Chat rate limiting** stays with F58-B, as F55-B recorded.

## Tests

`cargo test --workspace --locked -- accept_f55_c_ --include-ignored` → 7
tests discovered, executed, all passing.

- `accept_f55_c_wrong_password_full_lobby_and_content_mismatch_return_distinct_errors`
  — the minimum scenario (AC03): three refusals, three `JoinError`
  variants, three `message_key`s, three lines; refused joins seat nobody and
  leave the screen on the join form with its refusal kept.
- `accept_f55_c_the_join_form_refuses_a_bad_entry_before_any_request` — the
  form's own bounds (address length/control characters, empty address,
  domain-refused callsign) and the host form's unset entries; nothing
  reaches the lobby.
- `accept_f55_c_team_loadout_chat_and_a_host_ban_travel_to_the_lobby_and_back`
  — loadout, team, readiness and chat as requests; chat displayed literally
  (markup shown, not escaped); mute client-local; **AC01** through the
  screen: the host bans a weapon a ready member carries, the lobby revokes
  the readiness, the member's screen shows the reason; a member's ban is
  refused by the lobby's own authority check.
- `accept_f55_c_leaving_tears_the_screen_down_and_a_corrected_form_retries`
  — a refused join keeps the form, the corrected form joins, `leave`
  removes the member from the lobby and resets the screen, the retry
  allocates a fresh peer id, `back` tears the room down and then discards
  the draft, and the host's own departure follows `HostLoss`.
- `accept_f55_c_the_stage_table_refuses_every_action_outside_its_stage` —
  every action against every stage, focus reset and focus bounds.
- `crates/cs_net/tests/accept_f55_c_join_refusals.rs` — `JoinError`'s keys
  and lines directly: the three named refusals, and one key/line per
  variant.
