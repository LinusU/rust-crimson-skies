# F49-D.03-FU-RULES-END (#1638): how each original Instant Action mission type ends

Task #1638, branch `rally/1638-measure-and-bind-each-original-ia-missio`.
Follow-up of #1582 (`docs/findings/2026-10-18-f49-d-03-fu-faction-survivability.md`)
under parent #1583 (F49-D.03-FU-RULES): measures, per `mission_type`, what the
original's Instant Action end check actually tests, then binds the measured
end condition, respawns and deadline into the retail preset catalog.

## Evidence class

**`static`** — everything below is static analysis of the owner-supplied
decrypted engine image (`$CS_ENGINE_IMAGE`, sha-256 `43540fc9…6c37d75`, load
base `0x400000`) and of the retail `ZBD/*/IA*/zrdr.zbd#ia.zrd` descriptors
(installation sha-256 `b4e780ab84cf31d85b8452fbfcec1478137768e32d9a75ccedc4c1847c631978`).
No original executable ran; nothing here is `verified_original`.

## The mission type index

* `ia.zrd` `mission_type` → index: parser `0x458c20` compares the value
  case-insensitively (`_stricmp` through `[0xa20214]`) against five strings:
  `0x6253dc` `"dogfight_ace"` → returns the `stricmp` result `0`; `0x6253ec`
  `"dogfight_squadron"` → `1` (`0x458c56`); `0x625400` `"zeppelin_run"` → `2`
  (`0x458c6e`); `0x625410` `"ground_target"` → `3` (`0x458c86`); `0x625420`
  `"stunt_flying"` → `4` (`0x458c9a`). Any other name returns `ebx = 5`
  (`0x458c33`), the sentinel.
* Its caller (`0x4593d7` inside the scenario-record reader) stores the index
  into the record's `+0` field unless it is the sentinel — so an *unrecognised*
  `mission_type` leaves the record's initialised `0` (`mov [ebp], 0` at
  `0x458ffa`, inside initialiser `0x458ff0`), which is `dogfight_ace`.
* Index → name for display: `0x458cb0` jumps `[ecx*4 + 0x458ce0]` (table
  `0x458ce0` = `0x458cc2/0x458cc8/0x458cce/0x458cd4/0x458cda`), producing
  `0x625430/0x625440/0x625454/0x625464/0x625474` — the same five names.
* The spawn-points enabler `0x45a150` calls the same parser twice: the
  `disallow_missions` loop (`0x45a1a0`, names `0`..`4` clear the record's
  `+0x718fe0 + type*20` byte) and the `spawn_points` loop (`0x45a1ee`, calling
  `0x459ef0` per enabled type). Sentinel `5` is skipped at `0x45a1a8`/`0x45a1f6`.
* The Instant Action menu writes the type directly: `[0x64aba0]` `0..3` jumps
  table `0x4175d8` (`0x41754d`) → `mov [0x718cd8], 0|1|4|2` (`0x417554`,
  `0x417560`, `0x41756c`, `0x417578`). Menu rows produce types `0,1,4,2` — no
  menu row writes `3` (`ground_target`), matching `ground_target`'s absence
  from every retail directory's offered list.
* The live type the mission runs under is the global `[0x718cd8]`. The end
  check reads it once into `ebx` (`0x45b9e9`).

## The end check `0x45b9d0`

Called from `CZMission::Update` (`0x46a490`) at `0x46a5b9`, gated on
`0x4639b0` (mission state == 3) at `0x46a5b0`..`0x46a5b7`:

```
0x46a5b0: e8 fb 93 ff ff   call 0x4639b0
0x46a5b5: 84 c0            test al, al
0x46a5b7: 74 05            je 0x46a5be
0x46a5b9: e8 12 14 ff ff   call 0x45b9d0
```

The flight frame calls `CZMission::Update` only while the player vehicle's
`+0x91d` byte is clear (`[0x71c298]` is the player vehicle; `bl` is `0`):

```
0x4a09b1: a1 98 c2 71 00        mov eax, [0x71c298]
0x4a09b6: 38 98 1d 09 00 00     cmp byte [eax + 0x91d], bl
0x4a09bc: 75 0c                 jne 0x4a09ca        ; player down → skip update
0x4a09be: b9 80 b4 71 00        mov ecx, 0x71b480
0x4a09c3: e8 c8 9a fc ff        call 0x46a490       ; CZMission::Update
```

Because the world/damage update precedes the mission update in the frame
(F37-D-FU2), a tick on which the player's `+0x91d` is already set cannot run
the end check at all — a win is never awarded while the player is down, so a
mutual wipe resolves against the player.

### Win path

`0x45be40`: `push 1; mov ecx, 0x71b480; call 0x463c10` then
`push 0x40400000 (3.0f); push 1; mov ecx, 0x71b480; call 0x463c30`.
`0x45be5d` is the no-win return (epilogue only).

### The registry scan and the settled predicate

All five types share the vehicle registry list at `[0x71dabc]` (a
doubly-linked list whose node `+8` holds the vehicle record). A vehicle whose
team field `+0x8` is `<= 1` is skipped (`cmp dword [eax+8], 1; jle` at
`0x45ba10`/`0x45ba56`) — the predicates test only the opposing side.

A vehicle is **settled** differently per branch:

* **Type 0 `dogfight_ace`** (`0x45b9fd`, reached when `[0x718cd8] == 0`): for
  each opposing vehicle, `+0x91d` must be **set** and `+0x91f` must be
  **clear**:

  ```
  0x45ba16: 8a 98 1d 09 00 00   mov bl, [eax + 0x91d]
  0x45ba1c: 84 db               test bl, bl
  0x45ba1e: 0f 84 39 04 00 00   je 0x45be5d          ; not down → no win
  0x45ba24: 8a 98 1f 09 00 00   mov bl, [eax + 0x91f]
  0x45ba2a: 84 db               test bl, bl
  0x45ba2c: 0f 85 2b 04 00 00   jne 0x45be5d         ; 0x91f set → no win
  ```

  The whole list passing jumps `0x45be40` (`0x45ba38`). `+0x945` is **never
  read** in this branch: a spawned-asleep opponent (which `0x4b0f40(v,1)`
  writes `+0x945 = 1`, `+0x91d = 1`, `+0x91e = 0` — #681, see
  `docs/findings/2026-10-15-m01-aiv-layout.md` §4) already satisfies the
  type-0 predicate.

* **Types 1–4 shared loop** (`0x45ba3d`): a vehicle counts settled only when
  `+0x945` is **clear** (awake) **and** `+0x91d` is **set** **and** `+0x91f` is
  **clear**:

  ```
  0x45ba5c: 80 b8 45 09 00 00 00  cmp byte [eax + 0x945], 0
  0x45ba63: 75 12                 jne 0x45ba77       ; asleep → unsettled
  0x45ba65: 80 b8 1d 09 00 00 00  cmp byte [eax + 0x91d], 0
  0x45ba6c: 74 09                 je 0x45ba77        ; not down → unsettled
  0x45ba6e: 80 b8 1f 09 00 00 00  cmp byte [eax + 0x91f], 0
  0x45ba75: 74 11                 je 0x45ba88        ; settled → next vehicle
  0x45ba77: 39 90 88 03 00 00     cmp dword [eax + 0x388], edx
  0x45ba7d: c6 44 24 13 00        mov byte [esp + 0x13], 0   ; flag: unsettled seen
  0x45ba82: 0f 84 fb 02 00 00     je 0x45bd83        ; unsettled in current wave → tail
  ```

  `edx` is the wave counter `[0x718cd0]`; `+0x388` is the vehicle's wave
  group. An unsettled vehicle in the **current** wave jumps to the tail with
  flag `0` (no win); one in a *later* wave merely clears the flag and the scan
  continues.

### Wave advance and the dormant wake (the original's only "respawn")

After the scan, flag `[esp+0x13] == 1` (nothing unsettled anywhere) jumps to
the per-type tail `0x45bd83`. Flag `0` with nothing unsettled in the current
wave reaches `0x45ba9a`:

```
0x45ba9a: 42                    inc edx
0x45ba9b: 83 fb 02              cmp ebx, 2
0x45ba9e: 89 15 d0 8c 71 00     mov [0x718cd0], edx     ; wave counter += 1
0x45baa4: 75 64                 jne 0x45bb0a            ; types 1/3/4 → wake path
```

For every type but 2, `0x45bb0a`..`0x45bd7d`
wakes every vehicle of the new current wave: the loop at `0x45bbff` selects
vehicles whose `+0x388` equals the counter (`0x45bc08`) and calls
`0x4b0f40(vehicle, 0)` (`0x45bc17`, argument `edi = 0` — **wake**, not a new
spawn), placing each at a spawn point drawn from the type's `0x718fe0 +
type*20` record at least 500 m from the player — `0x538880` returns the
squared distance, and `fcomp [0x6036c0]` gates on `250000.0f = 500²`
(`0x45bb6c`; a random pick `div esi` at `0x45bbbd`).

For `zeppelin_run` (`ebx == 2`), `0x45baa4` keeps the wave counter advancing
but writes it only into the bound zeppelin's generator record: group size
`+0x80` accumulates the current-wave vehicle count (`0x45baf6`), wave index
`+0x64` takes the counter (`0x45bb02`), then `jmp 0x45bd83`. The vehicle scan
never awards the win for type 2.

### Per-type tail (`0x45bd83`)

* **Type 3 `ground_target`** (`0x45bd83`): the bound target object
  `[0x718f50]` ends it — win when the object is absent, or when its
  `vtable+0x14` call returns nonzero:

  ```
  0x45bd83: 83 3d d8 8c 71 00 03  cmp dword [0x718cd8], 3
  0x45bd8c: 8b 0d 50 8f 71 00     mov ecx, [0x718f50]
  0x45bd92: 3b cf                 cmp ecx, edi
  0x45bd94: 74 0e                 je 0x45bda4        ; absent → flag 1 → win
  0x45bd96: 8b 01                 mov eax, [ecx]
  0x45bd98: ff 50 14              call [eax + 0x14]
  0x45bd9b: 84 c0                 test al, al
  0x45bd9d: c6 44 24 13 00        mov byte [esp + 0x13], 0
  0x45bda2: 74 05                 je 0x45bda9        ; false → no win
  0x45bda4: c6 44 24 13 01        mov byte [esp + 0x13], 1
  ```

  The spawn binds the wrapper object at `0x45b1de` (`mov [0x718f50], eax`);
  for the wrapper class (vtable `0x60886c`, entry `+0x14` = `0x4a5a70`) that
  call returns the wrapped vehicle's `+0x91d` (`mov eax, [ecx+4]; mov al,
  [eax + 0x91d]; ret` at `0x4a5a70`) — the bound ground target's down byte.

* **Type 4 `stunt_flying`** (`0x45bda9`): every gate record in the vector
  `[0x718f78, 0x718f7c)` must be consumed — gate `+0x48` clear **or** `+0x40`
  set:

  ```
  0x45bdd5: 8a 59 48   mov bl, [ecx + 0x48]
  0x45bdd8: 84 db      test bl, bl
  0x45bdda: 74 0f      je 0x45bdeb          ; consumed
  0x45bddc: 8a 59 40   mov bl, [ecx + 0x40]
  0x45bddf: 84 db      test bl, bl
  0x45bde1: 75 08      jne 0x45bdeb         ; consumed
  0x45bde3: c6 44 24 13 00                  ; else flag 0, keep scanning
  ```

  For each consumed gate the scan also clears the parallel marker record
  `[0x718f88][i]`'s `+0x4d` byte (`0x45bdeb`..`0x45bdf4`). An empty gate list
  or all-consumed falls through to the win path. The gate vector is bound by
  the type-4 spawn at `0x45b56c`.

* **Type 2 `zeppelin_run`** (`0x45be01` → `0x45be0a`): the bound zeppelin
  object `0x718fd0[4 * [0x718f2c]]` ends it — win when the object is absent,
  when its component list `[+0x4c, +0x50)` is empty (`sub` then
  `test edx, 0xfffffffc` at `0x45be22`..`0x45be2d`), or when its `+0x06` byte
  is set:

  ```
  0x45be0a: 8b 15 2c 8f 71 00     mov edx, [0x718f2c]
  0x45be10: 8b 04 95 d0 8f 71 00  mov eax, [edx*4 + 0x718fd0]
  0x45be17: 3b c7                 cmp eax, edi
  0x45be19: 74 25                 je 0x45be40        ; absent → win
  0x45be1b: 8b 48 4c              mov ecx, [eax + 0x4c]
  0x45be1e: 3b cf                 cmp ecx, edi
  0x45be20: 74 1e                 je 0x45be40        ; list begin null → win
  0x45be22: 8b 50 50              mov edx, [eax + 0x50]
  0x45be25: 2b d1                 sub edx, ecx
  0x45be27: f7 c2 fc ff ff ff     test edx, 0xfffffffc
  0x45be2d: 74 11                 je 0x45be40        ; list empty → win
  0x45be2f: 8a 48 06              mov cl, [eax + 6]
  0x45be32: 84 c9                 test cl, cl
  0x45be34: 74 27                 je 0x45be5d        ; +0x06 clear → no win
  ```

  The zeppelin records are bound by the type-2 spawn `0x45b893`
  (`0x718f98`/`0x718fd0`).

* **Types 0 and 1** take no tail branch: type 0 won or returned inside its own
  branch; type 1 falls through the three `cmp [0x718cd8], 3|4|2` rejects to
  `0x45be38`, where flag `[esp+0x13]` — `1` only when the shared loop found no
  unsettled opposing vehicle anywhere — gates the jump into `0x45be40`.

### The measured negatives, uniform over the five types

* **No deadline.** `0x45b9d0`..`0x45be5f` contains no read of the tick/clock
  globals (`0x71c470` et al.) and no `call` to a timer; no mission type ends
  on time. `deadline_ticks` is `None` everywhere.
* **No respawn budget.** The only `0x4b0f40` call site inside the check is
  `0x45bc17` with argument `0` (**wake** a declared-but-dormant wave member —
  part of `WavesCleared`'s wave semantics), never `(vehicle, 1)` sleep and
  never a fresh spawn of a destroyed actor's replacement. `respawns` is
  `RespawnBudget::None`.
* **No tie for the player.** The win predicates read only opposing vehicles
  and the bound objects; the player's `+0x91d` is consulted once — by the
  caller gate `0x4a09b6`, which *pre-empts the check entirely*. A tick that
  would both down the player and complete the opposition's destruction cannot
  award the win, so `tie_outcome` is `OppositionFavour`.

## The byte flags, as findings already establish them

* `+0x945` — **asleep**: `0x4b0f40(vehicle,1)` sets it (with `+0x91d`,
  `+0x91e` cleared) and deactivates the node; `0x4b0f40(vehicle,0)` clears all
  four (`docs/findings/2026-10-15-m01-aiv-layout.md` §4, task #681).
* `+0x91d` — **down**: set by the sleep setter and by destruction paths (the
  player gate `0x4a09b6`, the wingman "leader awake" read
  `docs/findings/2026-10-17-m01-wingman-formation-control-law.md`, and the
  ground-target `0x4a5a70` all use it as the down/done signal).
* `+0x91f` — a second status bit, cleared on wake/registration
  (`docs/findings/2026-10-19-m01-launch-body-pose.md`,
  `docs/findings/2026-10-19-t1601-status-bit-consumers.md`). Its meaning is
  **unmeasured**; what is measured is only that both elimination predicates
  require it clear — a vehicle that is down *and* flagged `+0x91f` does not
  count toward the win.
* `+0x388` — the vehicle's wave-group index, compared against the wave
  counter `[0x718cd0]`.

## The production binding

`cs_content::instant_action::measured_ia_victory_rules` binds, per
`mission_type` name, the [`VictoryCondition`] whose doc names the byte
predicate above, with `RespawnBudget::None`, no deadline and
`TieOutcome::OppositionFavour`; a name outside the measured vocabulary returns
`None` (the survey already refuses it through `IA_MISSION_TYPE_VOCABULARY`).

The five measured variants extend the enum — the designed
`EliminateEnemies`/`LastSideStanding`/`SurviveToDeadline` cannot express the
bound-object predicates (zeppelin, target wrapper, gate list) or the dormant
wave semantics. `VictoryCondition::DESIGNED` is the offered subset: a custom
scenario may never pick a condition that names objects only the original
mission-type spawn creates, so `ScenarioOptions::try_new` validates the
offered list against `DESIGNED` and `retail_scenario_options_with_pilots`
offers exactly it.

`cs_app::ui::instant_action::retail::directory_presets` calls
`with_measured_rules` after `new_unmeasured_rules`, so each retail preset now
carries `Declared` rules — `lower_preset` gets one refusal closer to
launching (difficulty is still unmeasured). `evaluate_outcome`
(`cs_app::ui::instant_action::normalize`) evaluates the measured predicates
against the snapshot's terms: `alive` ↔ `+0x91d` clear, `pending` ↔ `+0x945`
set (a pending enemy satisfies `OppositionDown` but blocks `WavesCleared`),
and `objective_done` standing in for the bound non-actor object; the
player-down gate is the `0x4a09b6` pre-emption.

Claim id for this measurement: `f49.d.03.ia-rules-end` (`IA_RULES_END_CLAIM`).

## Unknowns recorded, not filled

* `+0x91f`'s own meaning — required clear in the elimination predicates;
  nothing else measured here.
* The zeppelin `+0x06` byte and the component-list `[+0x4c, +0x50)` fields of
  the bound object — read exactly as the check reads them; their names are
  unmeasured.
* The gate records' `+0x48`/`+0x40` bytes and the marker `+0x4d` — the check
  treats "`+0x48` clear or `+0x40` set" as "consumed"; what writes them is
  unmeasured (the type-4 spawn `0x45b56c` builds the records).
* The wave-group assignment `+0x388` and the spawn-point records
  `0x718fe0..0x719044` (five 20-byte records) — the 500 m distance gate
  (`fcomp [0x6036c0]`) and the random pick are measured; the records' other
  fields are not.
* Whether `tie_outcome` matters at all in practice: the player-down
  pre-emption makes a true `OppositionDown`/`WavesCleared` tie unreachable in
  the original (the check cannot run with the player down); the declared
  `OppositionFavour` is recorded for the shared evaluator's `tie` signature.
* `difficulty` per preset stays unmeasured (`f49.d.03.unmeasured.difficulty`)
  — `lower_preset` still refuses every retail preset, now naming the
  difficulty rather than the rules.
