## Item 1: the 33,864 B loop

* The DirectSound buffer is created from a source object whose length word
  (`[src+0x10]`) is the buffer size and whose bytes (`[src+0x28]`) are copied in
  with `Lock`/`Unlock` (`0x59b5e0`, the `zsnd_create.cpp` creator; its dispatcher
  `0x59b580` picks it or `0x59b950` by `[0x639cb4]`). The creator does not
  resize, pad or loop-extend the data, so the logged length is the length the
  *loader* produced, not an artefact of buffer creation (`static`, reading of
  `0x59b616..0x59b750`). The engine imports `acmStreamOpen/Size/Convert`, so
  the loader decodes ADPCM through ACM.
* Test `accept_parity6_m01_audio_11_33864_matches_no_member_under_any_length_reading`
  (retail, ignored without `CS_GAME_DIR`) checks all 2,521 `soundsh.zbd` and
  2,520 `soundsl.zbd` members: none decodes to 33,864 B, half, double, or the
  decoded size minus one sample. This extends the earlier test
  `accept_parity6_m01_audio_01_33864_matches_nothing_in_the_installation`.
* 33,864 B is 16,932 16-bit samples (1.536 s at 11,025 Hz). It is not a multiple
  of the MS ADPCM (1,000 B per 256 B block) or IMA (1,010 B) lattices the
  11,025 Hz members fall on, so it is not an ACM decode of an archive member.
  Retail 11,025 Hz members near this size are all round (`31000..37000` in
  steps of 1,000) or on the 1,010 lattice (`33,330`, `34,340`); none is 33,864.

Still unknown: the member, or whether the log's buffer is a non-archive source
(for example a streamed or CD-path buffer, `zsnd_cd.cpp`). Affected content: the
owner's 15.0 s voice and its 11,025 -> 22,050 Hz rate step.
